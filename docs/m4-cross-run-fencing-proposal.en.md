# M4.2 proposal: cross-run repository mutation authority

**Status: PROPOSAL / AWAITING REVIEW.** M3 and M4.1 are frozen. This document defines the contract to review before changing either persistence adapter. M4.2 proves durable cross-run fencing; M4.3 owns complete concurrent-run Temporal/worker acceptance.

## Evidence and identity gate

- `PersistedRun.repositoryId` comes from the approved `RepositorySnapshot.repositoryId` (`libs/run-preparation/src/lib/local-runtime-binding-policy.ts`). The Git snapshot provider hashes the _raw_ `origin` URL, or, without an origin, `local-root\0<absolute path>` (`libs/workspace-git/src/lib/git-repository-snapshot-provider.ts`). Thus matching IDs are useful immutable evidence, but different remote URL spellings and path-based IDs across hosts do **not** establish globally consistent repository identity. A commit, working-tree fingerprint, and checkout path identify other things and must not be substituted for a repository scope.
- Before admitting a global lease, resolve the approved run's immutable repository ID to a **registered repository authority scope ID** in the same authority store. Registration must explicitly reconcile alternate origin URLs/clones or a no-origin repository; an unregistered or ambiguous ID fails closed. Bind `(runId, approved repositoryId, authorityScopeId)` immutably during run creation or a one-time verified migration of an existing run. A caller-supplied scope string alone must not rebind an already approved run. The registration/alias policy and treatment of existing runs are a design gate, not an assumption that the current hash is globally canonical.
- Both contenders must use the _same configured Forge authority backend and database_. `FORGE_AUTHORITY_ID` currently identifies a deployment's backend/database/schema/role; it is **not** the repository scope ID. Separate authority stores cannot provide global fencing without an explicitly shared authority service.

## Proposed provider-neutral contract

Introduce `GlobalMutationLease` as the authoritative record, distinct from the existing per-run `WriteLease`. The latter contains a per-record `version`, run/task/agent and local `ACTIVE | RELEASED | STALE` lifecycle; its version is **not** a monotonic generation across owners. Keep the existing `WritableResource` hierarchy and `areWritableResourcesConflicting` semantics, including symbol ancestor relationships; do not reduce conflicts to equality of serialized keys.

| Contract item | Required meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scope         | Immutable `authorityScopeId` resolved from the approved run's repository identity; resource IDs are interpreted **within** that scope. `shared-resource` is scoped to this repository unless a separate explicit global namespace is designed.                                                                                                                                                                                                                                                                                                |
| Resource      | Reuse structured `WritableResource`: project, file, symbol with ancestors, or shared-resource. Project covers files/symbols; file covers symbols; related symbols conflict; identical shared resources conflict. Add an explicit repository-wide resource discriminant and overlap rule before using it for unclassified mutations or Git integration; the current union has **no** repository-wide resource. Until then, unclassified mutation fails closed.                                                                                 |
| Owner         | `runId`, `taskId`, `attemptId`, `agentId`, optional workspace identity and a durable claim ID. A different attempt, even in the same run, is a different owner. Global lease IDs are store-generated/unique; local lease IDs must not be assumed global.                                                                                                                                                                                                                                                                                      |
| Generation    | Store-allocated monotonically increasing, non-reused **repository-scope token allocation sequence** (e.g. checked 64-bit integer). Every grant receives a token; a new owner after verified release/reclamation gets a higher token. A disjoint grant also advances the allocation sequence but **does not invalidate another still-active lease**: validate the token against its exact lease/owner/resource record, not against the latest scope counter. Overflow fails closed. Lease `version` separately supports heartbeat/release CAS. |
| States        | `ACTIVE`, `HELD_UNCERTAIN` (including crash, `UNKNOWN`, or evidence marked stale), and `RELEASED`. Neither elapsed time nor `WriteLease.state === 'STALE'` by itself authorizes another run. Retain immutable grant/release/reclamation evidence.                                                                                                                                                                                                                                                                                             |
| Recovery      | `recoverRepositoryMutationAuthority(scopeId)` returns all unresolved owners, resources, tokens, versions and evidence across **all** runs, including uncertain owners. Reads must not silently filter to `recoverRun(runId)`.                                                                                                                                                                                                                                                                                                                 |

Candidate APIs (names illustrative): `registerRepositoryAuthority`, `claimGlobalMutation({runId,taskId,attemptId,resources,claimId}) -> granted(leases,token) | blocked(conflicting owners)`, `assertCurrentMutationToken({scopeId,runId,attemptId,leaseIds,token,resource})`, `heartbeatGlobalMutation(token, expectedVersion)`, `releaseGlobalMutation(token, expectedVersion, stopEvidence)`, `markMutationUncertain(...)`, `reclaimUncertainMutation(...verifiedQuiescenceEvidence)`, and `recoverRepositoryMutationAuthority(scopeId)`. Validate that every requested resource belongs to the approved immutable run scope. A retry by the _same_ owner/claim returns the same durable grants and token; a changed resource set or claimant under the same claim ID fails closed. Return blockers in stable order; "deterministic loser" means an unambiguous `blocked` result without partial mutation evidence, **not** a promise that a particular run ID wins independent of transaction order.

## Atomic admission and actual write boundary

1. Under one database-serialized repository-scope transaction, validate the bound run is `ACTIVE`, the attempt is authorized, and all requested resources. Compare against every `ACTIVE` or `HELD_UNCERTAIN` global lease using the existing structural overlap relation. If conflicting, return `blocked` with **zero** newly persisted mutation claims, local lease evidence, or attempt advancement. Otherwise allocate the next token(s) and commit all global leases, local projection/attempt claim, and ownership evidence together. Multi-resource acquisition is all-or-nothing in canonical resource order.
2. PostgreSQL may lock a single scope row `FOR UPDATE` (creating it through a unique constraint before the admission transaction) so even disjoint resources serialize admission while remaining simultaneously ownable. SQLite may use an immediate write transaction in the shared file. Do not implement `SELECT absent` followed by an unlocked insert. Repository-scope serialization must also cover cancellation versus claim and release/reclaim versus acquisition; specify one lock order (scope before affected run rows) for every participating transaction.
3. **All mutation paths**, including predicted builder leases, repair, dynamically requested tool writes, scope expansion, and Git integration, must check current durable ownership and the expected generation at the boundary where side effects can begin. An `AgentToolRuntime` that trusts its cached `InMemoryWriteGuard` lease and then calls `writeFile` is not fenced. Existing `claimBuilderStart`, `claimRepairStart`, `claimIntegrationStart` and `persistLease` cannot silently create or extend cross-run authority in separate transactions. Define a provider-neutral fenced mutation port and make claim/lease transitions and authority checks part of its persisted contract. No local map, Temporal state, or checkout isolation may grant authority.
4. A generation check alone cannot revoke an **already in-flight** arbitrary external write between validation and its side effect. Transfer to a new owner requires independently demonstrated quiescence of the former process/tool/Git operation, or a sink capable of rejecting stale generations atomically. M4.2 must prove a stale owner is rejected at every controlled mutation entry after transfer; it must not claim to stop an uncooperative process already writing a raw filesystem path. If quiescence cannot be proved, retain `HELD_UNCERTAIN` and block replacement indefinitely pending operator settlement.

## Release, cancellation and recovery

| Event                                                                                  | Global authority effect                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CANCEL_REQUESTED`                                                                     | Atomically disallow **new** grants for that run; retain existing leases/claims until controlled work stops or is settled.                                                                                                                                                                    |
| Builder/repair success or confirmed pre-start failure                                  | Release the exact owned resources only after the external mutation has stopped and durable outcome is recorded; CAS the current token/version.                                                                                                                                               |
| `UNKNOWN`, heartbeat loss, worker crash, unconfirmed abort, unfinished Git integration | Keep authority blocking as `HELD_UNCERTAIN` or `ACTIVE`. A clock deadline or process absence is not a release.                                                                                                                                                                               |
| Operator settlement / verified recovery                                                | Record explicit evidence that the former actor cannot mutate; atomically revoke/close old ownership. Allocate a strictly higher generation **when the next grant is admitted**. Old token checks must then fail.                                                                             |
| `CANCELLED`, `FAILED`, `COMPLETED`                                                     | Terminal state alone must not auto-delete a live or uncertain global owner. Finalization requires all applicable external mutation claims settled/released; if current same-run terminal behavior differs, M4.2 must gate **global** release without silently rewriting frozen M3 semantics. |
| Restart                                                                                | New worker recovers the scope-wide unresolved owners and generations from persistence, never just the current run's in-memory guard.                                                                                                                                                         |

Existing `STALE` local leases are useful evidence for same-run scheduler wake-up, but they cannot be promoted directly to permission for another run while an external actor might still write. Exact lifecycle integration and operator settlement must be reviewed before implementation.

## One shared semantic suite, two real backends

Add one backend-neutral persistence contract factory (no duplicated SQLite/PG assertions) with isolated authority-store fixtures, two run IDs, two connections, and a common repository scope:

1. Same scope + project/file/symbol-ancestor or matching shared-resource conflict: exactly one grant; loser has no claim, attempt advancement, or lease residue; exact retry returns the winner's original token. Different scopes and disjoint resources can both be admitted.
2. Multi-resource partial conflict rolls back **all** resources. New process/connection recovers scope-wide winner and blockers; run-only recovery cannot be used as a substitute.
3. Wrong run/scope/attempt/resource/token or stale generation cannot acquire, release, heartbeat, or enter a controlled mutation. After evidence-backed handoff, generation strictly increases; the old actor cannot mutate even if it retained a formerly `ACTIVE` local lease.
4. Cancellation-first rejects builder, repair, dynamic write, and integration claims without durable mutation evidence. In-flight cancellation does not fabricate a release. `UNKNOWN`/crash/time alone remain blocking; confirmed stop plus operator settlement enables handoff, and premature terminalization cannot erase unresolved authority.
5. Shared fixtures run against two independent SQLite connections to the same file and two independent PostgreSQL connections to the same migrated schema and restricted role. Do not change the M4.1 same-run suite or infer cross-run correctness from it.

Add **PG-only controlled-overlap evidence**: connection A begins/locks the repository scope and pauses, connection B's conflicting claim is demonstrably waiting on A (e.g. `pg_blocking_pids`), then A grants/commits; B returns blocked with no evidence. Repeat for cancellation racing claim and for verified release/reclaim racing a stale-token write. Plain `Promise.all` is insufficient. Assert persisted rows after each race from an independent third connection. SQLite must exhibit the same outcome but cannot serve as proof of overlapping PostgreSQL transactions.

## Explicit non-goals and review decisions

No multi-run Temporal E2E or worker-fleet scenario matrix (M4.3), scheduler/repository policy redesign, API/UI, automatic schema migration, or removal of SQLite. PostgreSQL schema changes need an explicit owner migration and version gate consistent with frozen M4.1C; runtime startup remains DDL-free. Full production concurrency and Git-side effects are M4.3, but the controlled mutation boundary must already be defined and tested in M4.2.

**Approve before implementation:** (1) registration/alias rules for origin URL variants and no-origin repositories, and whether historical runs require explicit rebinding; (2) scope of `shared-resource`; (3) whether integration takes a conservative repository-wide lease or a narrower proven resource set; (4) the quiescence proof and fenced write-sink boundary for external tools/Git; (5) whether terminal transitions with unresolved global leases reject or remain terminal while retaining blocking authority. Do not mark M4.2 CLOSED until both backends and real PG overlap pass and these decisions are implemented, not merely documented.
