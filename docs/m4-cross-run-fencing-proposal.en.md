# M4.2 proposal: cross-run repository mutation authority

**Status: REVISED PROPOSAL / AWAITING INDEPENDENT REVIEW; NOT APPROVED FOR IMPLEMENTATION.** M3 and M4.1 are PASS / CLOSED / FROZEN. This document defines the contract to review before changing either persistence adapter. M4.2 proves durable cross-run fencing; M4.3 owns complete concurrent-run Temporal/worker acceptance.

## Evidence and identity gate

- `PersistedRun.repositoryId` comes from the approved `RepositorySnapshot.repositoryId` (`libs/run-preparation/src/lib/local-runtime-binding-policy.ts`). The Git snapshot provider hashes the _raw_ `origin` URL, or, without an origin, `local-root\0<absolute path>` (`libs/workspace-git/src/lib/git-repository-snapshot-provider.ts`). Thus matching IDs are useful immutable evidence, but different remote URL spellings and path-based IDs across hosts do **not** establish globally consistent repository identity. A commit, working-tree fingerprint, and checkout path identify other things and must not be substituted for a repository scope.
- Before admitting a global lease, resolve the approved run's immutable repository ID to a **store-generated opaque repository authority scope ID** in the same authority store. A privileged registration/migration operation explicitly maps `repositoryId -> authorityScopeId`; each repository ID maps to at most one scope in that store. Raw-origin variants and no-origin repositories may be explicitly registered to the same scope, but URL normalization or apparent similarity never merges them automatically. Runtime claims cannot create aliases. Unregistered or ambiguous identity fails closed. Bind `(runId, approved repositoryId, authorityScopeId)` immutably during run creation. A historical run without a binding cannot obtain new global mutation authority until an audited one-time binding verifies its immutable approved repository ID; never silently rebind. Terminal historical runs that will never claim global authority need no compulsory backfill.
- Both contenders must use the _same configured Forge authority backend and database_. `FORGE_AUTHORITY_ID` currently identifies a deployment's backend/database/schema/role; it is **not** the repository scope ID. Separate authority stores cannot provide global fencing without an explicitly shared authority service.

## Proposed provider-neutral contract

Introduce `GlobalMutationLease` as the authoritative record, distinct from the existing per-run `WriteLease`. The latter contains a per-record `version`, run/task/agent and local `ACTIVE | RELEASED | STALE` lifecycle; its version is **not** a monotonic generation across owners. Keep the existing `WritableResource` hierarchy and `areWritableResourcesConflicting` semantics, including symbol ancestor relationships; do not reduce conflicts to equality of serialized keys.

| Contract item | Required meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scope         | Immutable `authorityScopeId` resolved from the approved run's repository identity; resource IDs are interpreted **within** that scope. `shared-resource` is scoped to this repository unless a separate explicit global namespace is designed.                                                                                                                                                                                                                                                                                                                                                                                      |
| Resource      | Extend structured `WritableResource` (project, file, symbol with ancestors, shared-resource) with `{ type: 'repository' }`. Within one scope, repository conflicts with every mutation resource; project covers files/symbols, file covers symbols, related symbols conflict, and identical scoped shared resources conflict. Git integration requires repository-wide authority; an unclassified mutation without a proven resource fails closed. The current union has **no** repository-wide member, so this is an implementation requirement, not an existing capability.                                                       |
| Owner         | `runId`, `taskId`, `attemptId`, `agentId`, optional workspace identity and a durable claim ID. A different attempt, even in the same run, is a different owner. Global lease IDs are store-generated/unique; local lease IDs must not be assumed global.                                                                                                                                                                                                                                                                                                                                                                            |
| Generation    | Store-allocated monotonically increasing, non-reused **repository-scope token allocation sequence** (e.g. checked 64-bit integer). **One token per atomic durable `claimId`, not per resource**: all leases of a multi-resource claim carry that token. A new claim after verified release/reclamation gets a higher token. A disjoint claim also advances the counter but **does not invalidate another still-active claim**: validate against its exact scope/claim/owner/resource/token/unresolved-state record, not the latest scope counter. Overflow fails closed. Lease `version` separately supports heartbeat/release CAS. |
| States        | `ACTIVE`, `HELD_UNCERTAIN` (including crash, `UNKNOWN`, or evidence marked stale), and `RELEASED`. Neither elapsed time nor `WriteLease.state === 'STALE'` by itself authorizes another run. Retain immutable grant/release/reclamation evidence.                                                                                                                                                                                                                                                                                                                                                                                   |
| Recovery      | `recoverRepositoryMutationAuthority(scopeId)` returns all unresolved owners, resources, tokens, versions and evidence across **all** runs, including uncertain owners. Reads must not silently filter to `recoverRun(runId)`.                                                                                                                                                                                                                                                                                                                                                                                                       |

Candidate APIs (names illustrative): `registerRepositoryAuthority` (privileged), `claimGlobalMutation({runId,taskId,attemptId,resources,claimId}) -> granted(leases,token) | blocked(conflicting owners)`, `assertCurrentMutationToken({scopeId,claimId,runId,attemptId,leaseIds,token,resource})`, `heartbeatGlobalMutation(token, expectedVersion)`, `releaseGlobalMutation(token, expectedVersion, stopEvidence)`, `markMutationUncertain(...)`, `reclaimUncertainMutation(...verifiedQuiescenceEvidence)`, and `recoverRepositoryMutationAuthority(scopeId)`. Validate that every requested resource belongs to the approved immutable run scope. A retry by the _same_ owner/claim returns the same durable grants and token; a changed resource set or claimant under the same claim ID fails closed. Dynamic scope expansion uses **a new claim ID and new token governing only the newly acquired resources**; it cannot silently enlarge an earlier claim. Return blockers in stable order; "deterministic loser" means an unambiguous `blocked` result without partial mutation evidence, **not** a promise that a particular run ID wins independent of transaction order.

## Atomic admission and actual write boundary

1. Under one database-serialized repository-scope transaction, validate the bound run is `ACTIVE`, the attempt is authorized, and all requested resources. Compare against every `ACTIVE` or `HELD_UNCERTAIN` global lease using the existing structural overlap relation. If conflicting, return `blocked` with **zero** newly persisted mutation claims, local lease evidence, or attempt advancement. Otherwise increment the scope counter **once per atomic `claimId`**, and commit its single token on every member lease together with the local projection/attempt claim and ownership evidence. Multi-resource acquisition is all-or-nothing in canonical resource order.
2. PostgreSQL may lock a single scope row `FOR UPDATE` (creating it through a unique constraint before the admission transaction) so even disjoint resources serialize admission while remaining simultaneously ownable. SQLite may use an immediate write transaction in the shared file. Do not implement `SELECT absent` followed by an unlocked insert. **Every transition that removes eligibility for new mutation authority**—`ACTIVE -> CANCEL_REQUESTED`, `ACTIVE -> FAILED`, `ACTIVE -> COMPLETED`, and `CANCEL_REQUESTED -> CANCELLED`—participates in the same repository-scope-before-affected-run-rows lock order as claim, release and reclaim. Include every other terminalizing path in that order; no run-row-first shortcut or opposite lock order. Scope and run state must be checked and committed atomically. Terminalization never implies release of an unresolved global owner.
3. **All mutation paths**, including predicted builder leases, repair, dynamically requested tool writes, scope expansion, and Git integration, must check current durable ownership and the expected generation at the boundary where side effects can begin. An `AgentToolRuntime` that trusts its cached `InMemoryWriteGuard` lease and then calls `writeFile` is not fenced. Existing `claimBuilderStart`, `claimRepairStart`, `claimIntegrationStart` and `persistLease` cannot silently create or extend cross-run authority in separate transactions. Define a provider-neutral `FencedMutationPort.execute({claimId,token,resource,sideEffect})` that gates a **real controlled mutation callback** on current durable authority; claim/lease transitions and authority checks belong to its persisted contract. The port must coordinate in-flight callbacks with quiescence/handoff; a token check just before an unsynchronized raw write alone is insufficient. No local map, Temporal state, or checkout isolation may grant authority.
4. A generation check alone cannot revoke an **already in-flight** arbitrary external write between validation and its side effect. Transfer to a new owner requires independently demonstrated quiescence of the former process/tool/Git operation, or a sink capable of rejecting stale generations atomically. M4.2 must prove a stale owner is rejected at every controlled mutation entry after transfer; it must not claim to stop an uncooperative process already writing a raw filesystem path. If quiescence cannot be proved, retain `HELD_UNCERTAIN` and block replacement indefinitely pending operator settlement.

## Release, cancellation and recovery

| Event                                                                                  | Global authority effect                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CANCEL_REQUESTED`                                                                     | Atomically disallow **new** grants for that run; retain existing leases/claims until controlled work stops or is settled.                                                                                                                                                                                                                                                                                                                                                                                                    |
| Builder/repair success or confirmed pre-start failure                                  | Release the exact owned resources only after the external mutation has stopped and durable outcome is recorded; CAS the current token/version.                                                                                                                                                                                                                                                                                                                                                                               |
| `UNKNOWN`, heartbeat loss, worker crash, unconfirmed abort, unfinished Git integration | Keep authority blocking as `HELD_UNCERTAIN` or `ACTIVE`. A clock deadline or process absence is not a release.                                                                                                                                                                                                                                                                                                                                                                                                               |
| Operator settlement / verified recovery                                                | Record explicit evidence that the former actor cannot mutate or that its sink atomically rejects stale writes; atomically revoke/close old ownership. Allocate a strictly higher token **when the next claim is admitted**. Old token checks must then fail.                                                                                                                                                                                                                                                                 |
| `CANCELLED`, `FAILED`, `COMPLETED`                                                     | Terminal state and mutation authority are independent durable facts. A run **may become terminal with unresolved authority** (notably post-start `UNKNOWN -> FAILED`); that `ACTIVE`/`HELD_UNCERTAIN` owner keeps blocking other runs until independently settled. Preserve any existing path-specific cancellation-finalization checks, but do not impose a universal "no terminal state while a global lease is unresolved" rule or auto-release on terminalization. Terminal transitions still take the scope-first lock. |
| Restart                                                                                | New worker recovers the scope-wide unresolved owners and generations from persistence, never just the current run's in-memory guard.                                                                                                                                                                                                                                                                                                                                                                                         |

Existing `STALE` local leases are useful evidence for same-run scheduler wake-up, but they cannot be promoted directly to permission for another run while an external actor might still write. Exact lifecycle integration and operator settlement must be reviewed before implementation.

## One shared semantic suite, two real backends

Add one backend-neutral persistence contract factory (no duplicated SQLite/PG assertions) with isolated authority-store fixtures, two run IDs, two connections, and a common repository scope:

1. Registered aliases sharing one opaque scope conflict; unregistered/ambiguous aliases and an unbound historical run cannot claim. Same scope + repository/project/file/symbol-ancestor or matching shared-resource conflict: exactly one grant; loser has no claim, attempt advancement, or lease residue. Different scopes and disjoint resources can both be admitted; a repository-wide claim blocks integration against every other mutation resource within its scope.
2. Multi-resource partial conflict rolls back **all** resources and the token allocation; an accepted claim allocates **one token** shared by all its leases, exact retry returns it, changed resources under that claim ID fail, and dynamic expansion takes another claim ID/token. A disjoint later claim with a higher token does not invalidate the earlier unresolved nonconflicting owner. New process/connection recovers scope-wide winners and blockers; run-only recovery cannot be used as a substitute.
3. Wrong run/scope/attempt/resource/token or stale generation cannot acquire, release, heartbeat, or enter a controlled mutation. After evidence-backed handoff, generation strictly increases; the old actor cannot mutate even if it retained a formerly `ACTIVE` local lease. Include a **backend-neutral boundary test**: after handoff, the old worker calls `FencedMutationPort.execute` with its old token and an injectable side-effect callback (or temporary-file write); the call rejects, **the callback is not invoked, file/content and durable evidence remain unchanged**. Testing only `assertCurrentMutationToken()` is insufficient.
4. Cancellation-first **or terminalization-first** rejects later builder, repair, dynamic write, and integration claims without durable mutation evidence. If a claim wins first, cancellation/terminal transition may proceed under frozen lifecycle rules, but that grant remains blocking until settled. `UNKNOWN`/crash/time alone remain blocking; confirmed stop plus operator settlement enables handoff. Exercise `ACTIVE -> FAILED`, `ACTIVE -> COMPLETED`, and `CANCEL_REQUESTED -> CANCELLED` as applicable, including `FAILED` with unresolved authority. Do not invent a terminal transition disallowed by an existing path-specific lifecycle guard.
5. Shared fixtures run against two independent SQLite connections to the same file and two independent PostgreSQL connections to the same migrated schema and restricted role. Do not change the M4.1 same-run suite or infer cross-run correctness from it.

Add **PG-only controlled-overlap evidence**: connection A begins/locks the repository scope and pauses, connection B's conflicting claim is demonstrably waiting on A (e.g. `pg_blocking_pids`), then A grants/commits; B returns blocked with no evidence. Repeat for `ACTIVE -> CANCEL_REQUESTED` **and terminalization** racing claim in both winner orders, and for verified release/reclaim racing a stale-token write. The stale-token case must additionally use the shared fenced-port callback test to prove the actual controlled side effect was not invoked. Plain `Promise.all` is insufficient. Assert persisted rows after each race from an independent third connection. SQLite must exhibit the same outcome but cannot serve as proof of overlapping PostgreSQL transactions.

## Explicit non-goals and review decisions

No multi-run Temporal E2E or worker-fleet scenario matrix (M4.3), scheduler/repository policy redesign, API/UI, automatic schema migration, or removal of SQLite. PostgreSQL schema changes need an explicit owner migration and version gate consistent with frozen M4.1C; runtime startup remains DDL-free. Full production concurrency and Git-side effects are M4.3, but the controlled mutation boundary must already be defined and tested in M4.2.

## Reviewed design rulings to implement

1. Register store-generated opaque scope IDs and privileged, uniquely mapped repository ID aliases explicitly: each repository ID maps to at most one scope, while multiple registered IDs may share a scope. No automatic URL merge and no silent historical-run rebinding. A historical nonterminal run must have its approved repository ID audited and bound before claiming global authority. Terminal historical runs without future claims need no backfill.
2. `shared-resource` identity is `(authorityScopeId, resourceId)` in M4.2; external cross-repository resources require a future separate namespace.
3. Add `{ type: 'repository' }` to the resource union, conflicting with **every** mutation resource in that scope, and require it for Git integration (branch/ref movement, rebase, integration checkout and fast-forward). No narrower file-only assumption until independently proven.
4. Handoff for raw filesystem, external agent and Git work requires proven quiescence: authoritative managed completion/cancellation acknowledgment, owned process exit **and** no controlled mutation in flight, completed/aborted Git operation, or explicit operator settlement with evidence. Heartbeat age, worker disappearance and local `STALE` are insufficient. Without proof, retain `HELD_UNCERTAIN` and deny replacement; only a future sink that atomically rejects stale tokens can relax quiescence.
5. Run lifecycle and mutation ownership are independent: `UNKNOWN` may lead to `FAILED` with blocking authority retained. Existing path-specific cancellation settlement rules remain; there is no universal prohibition on terminal state with unresolved authority. Every eligibility-removing transition still serializes scope-first against new claims.

M4.2 remains **DESIGN / AWAITING INDEPENDENT REVIEW** until these rulings and the three authority invariants (terminal lock order, one token per claim, controlled side-effect rejection) are approved. Do not mark M4.2 CLOSED until both backends and real PostgreSQL overlap pass and these decisions are implemented, not merely documented. M4.3 remains NOT STARTED.
